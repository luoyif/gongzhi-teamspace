# 知识流转：项目的第一性原则

1. 任务承载讨论：人、人机和未来多 Agent 的协作必须依附具体项目和任务。
2. 原始资料不可静默覆盖：上传文件、解析内容、纪要、决策与结果各自保留来源与版本。
3. 只有真实工具回执才算已执行：Trace 记录人、模型、工具、输出和审批，不编造隐藏推理。
4. 纪要与候选不直接成为组织事实：明确采用或验收后进入项目记忆；公开公司知识需另外授权。
5. 以最小上下文工作：最近请求是目标，历史作为背景，优先搜索片段，然后按需读取原件。
6. 权限不跨项目泄漏：普通成员只见获准项目；公开团队知识必须经过明确发布和可撤回快照。
7. 配置是可复用能力资产：Agent 配置职位，Skill 描述方法，MCP 连接外部资源，Plugin 执行平台动作，Harness 约束操作过程。
8. 存储数据一致性优先：SQLite 管理状态，Markdown 是可导出、可重建的知识投影。

    上传原件 -> 授权索引 -> 人/AI协作对话 -> 待核对整理
       -> 人工确认 -> 任务/日程/成果/记忆 -> 团队共享快照
       -> 可审核的 Skill 草稿 -> 员工按需装配使用

不把一段聊天自动推广成可信知识，也不允许导入文件中的提示词扩大工具权限。
当前一次调用一位 Agent；多 Agent 并行工作和 AI-AI 自主协作是待开发方向，不是已提供的能力。
